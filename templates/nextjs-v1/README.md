## Setup

### Prerequisites
- Node 20+, pnpm 9+
- A Supabase project ([supabase.com](https://supabase.com))
- A Cloudflare account with Workers for Platforms (only needed for deploy)

### Local development

```bash
# 1. Install dependencies
pnpm install

# 2. Configure environment
cp .env.example .env.local
# Edit .env.local with your Supabase URL + anon key + service role key

# 3. Apply database migrations
# Open Supabase SQL editor → paste contents of supabase/migrations/01-profiles.sql → Run
# (or via Supabase CLI: `supabase db push`)

# 4. Run dev server
pnpm dev
# → http://localhost:3100
# (port 3100 not 3000 — leaves :3000 free for JarvisFactory itself or other dev servers)
```

### Pre-ship checks

Before every deploy, the pre-ship gate must pass (SOP §6 + §14.3):

```bash
pnpm preship
# Runs: typecheck → lint → test
```

If any check fails, fix and re-run. Do not deploy with red checks.

### Cloudflare deploy

```bash
# 1. Set service role key as Cloudflare secret
wrangler secret put SUPABASE_SERVICE_ROLE_KEY

# 2. Build + deploy
pnpm deploy:cf
```

## The SOP §4.2 pattern — read this before writing any data mutation

Every action that touches data MUST follow this exact shape:

```typescript
// actions/example.ts
'use server'

import { z } from 'zod'
import { requireUser } from '@/lib/auth/require-user'
import { createSupabaseAdminClient } from '@/lib/supabase/admin'
import type { ActionResult } from '@/lib/types'

const inputSchema = z.object({
  title: z.string().min(1).max(200),
})

export async function createThing(formData: FormData): Promise<ActionResult> {
  // 1. Permission gate FIRST — redirects to /login if no session
  const user = await requireUser()

  // 2. Validate input with zod (SOP §4.3)
  const parsed = inputSchema.safeParse({ title: formData.get('title') })
  if (!parsed.success) {
    return { ok: false, error: parsed.error.issues[0]?.message ?? 'Invalid input' }
  }

  // 3. Write via ADMIN client, scoping by user.id (derived server-side, NOT from form)
  const admin = createSupabaseAdminClient()
  const { error } = await admin.from('things').insert({
    user_id: user.id,   // ← from requireUser, not formData
    title: parsed.data.title,
  })

  if (error) return { ok: false, error: error.message }
  return { ok: true, data: undefined }
}
```

Why: the RLS-respecting client's write context is unreliable on Cloudflare Workers — `auth.uid()` doesn't always reach Postgres. The admin client is the reliable write path; the `requireUser()` gate is the security boundary.
